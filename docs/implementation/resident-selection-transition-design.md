# Managed selection and publication transitions

The remaining deterministic decisions in `managed-selection.ts` belong in pure functions over explicit state and events. The existing `withResidentSelection` and `runOwnedGeneration` APIs remain the resource boundary. The shell owns claim acquisition/release, nested admitted candidate scopes, descriptor reads, registry publication, publication scope settlement and inode-checked retirement.

Candidate accumulation and publication authority use separate state types. Candidate state retains at most one opaque admitted exchange while the recursive shell keeps its actual scope open. A second compatible candidate refuses. A completed search chooses the compatible candidate before consulting capacity; capacity can refuse only an empty search. I/O failure never becomes absence or a retry event.

Publication state combines an attempt phase (unattempted, attempted, recorded receipt) with a scope phase (open, closing with owner outcome, settled). Requesting readiness consumes the attempt before directory refusal. Fencing prevents new attempts but permits a previously started publication to record its receipt while closing. The shell sends settlement only after joining the actual publication scope; that transition authorizes retirement of the exact receipt only for success or interruption-only exit. It retains evidence for every other outcome. A repeated settlement must not authorize another cleanup attempt.

The caller first records the begin decision, then reads the descriptor. Actual publication, synchronous receipt recording and selection-claim release form one uninterruptible ownership transfer. Fencing happens before scope closure; retirement selection reads the latest state after closure. Pure metadata cannot prove a process has retired or replace the real selection claim.

Two designs were compared under `/tmp/resident-selection-architecture-20261018`. A proposed an overloaded ownership-domain transition across selection/publication phases; B proposed separate candidate and publication protocols. Both initially missed the cancellation-safe resource transfer. The independent judge scored both 15/20 and preferred B's smaller API. Select B as the base, graft A's explicit closing/settled state and one-shot retirement authorization, and add the complete transfer correction. Reject the generic ownership union and a trivial claim-result dispatcher: the acquisition boundary already parses typed contention, and no pure state should simulate the lock.

The real-registry interruption test exposed the missing transfer in the baseline: the record could be written before interruption skipped receipt storage. Masking only publication and storage then exposed a held-claim deadlock because interruption skipped release. The complete transfer fixes both. The test checks the owner's final exit contains interrupts only and the registry directory is removed; it does not query an old registry capability after that directory has been retired.
