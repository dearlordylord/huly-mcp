# Как разработчики распространяют MCP-серверы

Исследовано 2026-10-22. Ограниченная выборка официальных инструкций разработчиков серверов и инструментов доставки. Это подтверждение существующих практик, а не статистика долей рынка. Внешние серверы в рамках исследования не запускались.

## Вывод

Записывать в конфигурацию клиента команду `npx …`, которая при необходимости скачивает пакет перед запуском, — обычный документированный способ подключения локального Node.js MCP. Так делают Microsoft Playwright, Upstash Context7 и эталонный Filesystem server. Следовательно, отдельная предварительная установка не является обязательной отраслевой практикой. В этих рассмотренных инструкциях фигурирует именно `npx`; оснований объявлять `pnpm dlx` самым распространённым вариантом нет. Источники приведены в таблице.

## Конкретные примеры

| Разработчик / продукт | Официальный пользовательский сценарий | Что устанавливается заранее |
| --- | --- | --- |
| Microsoft Playwright MCP | Стандартная конфигурация: `command: "npx"`, аргумент `@playwright/mcp@latest`; те же команды для Claude Code и других клиентов. [README](https://github.com/microsoft/playwright-mcp#readme) | Нужен доступный Node.js/npm runtime; инструкция регистрации MCP сама задаёт команду запуска пакета. |
| Upstash Context7 | Локально: `npx -y @upstash/context7-mcp`; удалённо: `https://mcp.context7.com/mcp`. Предлагаются оба сценария. [Инструкции клиентам](https://github.com/upstash/context7/blob/master/docs/resources/all-clients.mdx) | Для удалённого подключения локальный пакет сервера не нужен; для локального нужен доступный `npx`. |
| MCP reference Filesystem | Конфигурации `npx -y @modelcontextprotocol/server-filesystem …` и `docker run … mcp/filesystem`. [README](https://github.com/modelcontextprotocol/servers/blob/main/src/filesystem/README.md) | Node.js для `npx` либо Docker для контейнера; путь к разрешённым файлам передаётся явно. |
| MCP reference Git (Python) | `uvx mcp-server-git` рекомендован без отдельной установки пакета. Альтернативы: `pip install mcp-server-git`, затем `python -m mcp_server_git`, либо Docker. [README](https://github.com/modelcontextprotocol/servers/blob/main/src/git/README.md#installation) | `uv` для первого сценария; предварительная установка Python-пакета — отдельный поддерживаемый выбор, а не обязательный шаг. |
| GitHub MCP Server | Hosted HTTP endpoint `https://api.githubcopilot.com/mcp/`; локальная альтернатива `docker run … ghcr.io/github/github-mcp-server`; без Docker описана сборка Go-бинарника с последующим указанием его пути в `command`. [README](https://github.com/github/github-mcp-server#readme) | Hosted-вариант не требует локального сервера; локальный контейнер требует работающий Docker; сборка требует Go. |
| MCP Bundles / Desktop Extensions (`.mcpb`) | Пакет для установки локального сервера через поддерживающее desktop-приложение. Node bundle включает зависимости; binary bundle включает исполняемые файлы. [Формат и примеры](https://github.com/modelcontextprotocol/mcpb#readme) | Подготовку файлов берёт на себя автор bundle и поддерживающий клиент. Это отдельный канал доставки, не универсальный формат всех CLI-клиентов. |
| Codex, пример подключения Context7 | `codex mcp add context7 -- npx -y @upstash/context7-mcp`; в конфигурации также `command = "npx"`. [Документация Codex](https://learn.chatgpt.com/docs/extend/mcp) | Регистрация команды запуска не равна отдельной установке npm-пакета. |

## Что означает «скачивается при запуске»

`npx` использует `npm exec`: отсутствующий в локальных зависимостях запрошенный пакет устанавливается в каталог npm cache и добавляется в `PATH` запускаемой команды. `-y` подавляет запрос согласия на такую установку. Это не означает, что весь пакет заново скачивается при каждом запуске. [npm exec](https://docs.npmjs.com/cli/v11/commands/npm-exec/).

`pnpm dlx` тоже получает пакет из registry и запускает его binary без добавления пакета в зависимости проекта. Текущая документация перенаправляет на новое имя `pnx` и перечисляет `pnpm dlx` как alias; это не утверждение о версии pnpm, установленной у наших пользователей. [pnpm](https://pnpm.io/cli/dlx).

`uvx` — аналогичный подход для Python: изолированное окружение хранится в кеше и создаётся заново при его отсутствии. Отдельный `uv tool install` создаёт постоянно установленный инструмент. [Astral uv](https://docs.astral.sh/uv/concepts/tools/).

Отсюда следует практическое ограничение: конфигурация с package runner допускает первый запуск с загрузкой до начала MCP handshake. Это свойство способа доставки, а не доказательство ошибки сервера. Проверять отсутствие кеша и поведение клиента при задержке всё равно обязан разработчик продукта. Удалённый HTTP устраняет локальную установку сервера; предварительная установка или bundle переносят подготовку в отдельный этап. Эти варианты не устраняют собственные требования к подключению, авторизации или поддержке клиента.

## Следствие для Huly MCP

Наш подход запуска через package runner соответствует рассмотренным официальным примерам. Сам по себе переход с `pnpm dlx` на `npx` не устранит ожидание при пустом кеше. Для публичной инструкции `npx -y @firfi/huly-mcp@<version>` имеет прямые аналоги у перечисленных разработчиков и требует меньше предварительных инструментов, если Node.js/npm уже доступны. Предварительная установка может быть отдельным вариантом для контролируемых окружений; превращать её в обязательный ручной шаг только на основании этой выборки нельзя.

Это исследовательская рекомендация, а не изменение продукта или пользовательских настроек. Надёжность нашего конкретного запуска подтверждается отдельными реальными квалификационными тестами, а не наличием аналогичного README у других проектов.
